# Codex SOS v0.1 架构

## 目标

v0.1 只打通一条真正可用的 Windows 路径。

```text
一张截图或一句描述
        ↓
本机识字与最小只读检查
        ↓
官方体检、服务状态、相似公开问题
        ↓
固定规则判断与低风险建议
        ↓
四块大白话结果
        ↓
用户需要时才预览并保存公开材料
```

用户不需要找日志、抄版本、理解 GitHub 或决定该跑哪项检查。普通流程不追加问题。只有输入和自动证据都不足，而且错误判断可能带来明显风险时，判断引擎才允许给出一次大白话选择题。

## 技术方案比较

v0.1 比较过两个能在 Windows 做桌面应用的方案。

| 项目 | .NET 10 和 WPF | Python 和 PySide 6 |
|---|---|---|
| 双击体验 | 可发布自带运行环境的 x64 文件夹和每用户安装包 | 需要把 Python、Qt 与本机库一起冻结，启动和防病毒误报更难控制 |
| Windows 窗口截图 | 直接调用稳定的 Win32 窗口能力 | 需要 ctypes 或额外封装，最终仍依赖 Win32 |
| 剪贴板与界面 | WPF 内建 | Qt 内建，但打包 Qt 体积更大 |
| 本机 OCR | 随应用带英文 Tesseract 绑定，不需要联网 | Python OCR 生态丰富，但常带模型、解释器或额外本机依赖 |
| 运行官方体检 | `ProcessStartInfo` 可限制参数、输出和等待时间 | `subprocess` 同样可行 |
| Windows 故障记录 | 可直接使用系统进程与 XML | 可调用系统命令，但边界封装和发行物更分散 |
| 网络请求 | .NET 内建 `HttpClient` | 标准库或第三方 requests 均可 |
| 发布体积 | 自带 .NET 运行环境，体积不小但组成稳定 | Python、Qt、OCR 一起冻结通常更大，文件更多 |
| 自动测试 | 核心规则可用普通 .NET 可执行测试器；WPF 在 Windows 验收 | Python 测试方便，Qt UI 和冻结包仍需另做 Windows 验收 |
| 后续维护 | 一个 SDK、一个 UI 框架、一个 OCR 直接依赖 | Python、PySide、冻结工具、OCR 和本机 DLL 升级链更长 |
| 用户环境 | 不要求用户安装任何开发工具 | 也能做到，但冻结和防病毒兼容更容易波动 |

**选择 .NET 10 和 WPF。** 理由是它更接近 Windows 自带能力，能用一个工具链同时完成界面、系统检查、网络、测试和自带运行环境发布。Python 和 PySide 不是能力不足，主要问题是第一版会多出解释器、Qt、冻结工具与 OCR 的长期兼容面。

没有选择 WinUI 3，是为了避免再增加 Windows App SDK 部署层。没有把 Windows 系统 OCR 作为首选，是因为桌面应用的打包身份和发布方式会增加首发复杂度。v0.1 使用 TesserNet 0.8.0 随包提供的英文 Tesseract 能力，换来离线和零安装。这个依赖版本较旧，属于明确维护风险，必须由真实 OCR、依赖漏洞和干净机测试共同约束。

WPF 发布保持非单文件、非裁剪、非 AOT。目录里的文件会更多，但减少反射、本机库和 WPF 资源在激进优化下损坏的风险。

## 代码边界

```text
CodexSOS.App
├─ WPF 页面与大白话交互
├─ Windows 窗口截图和剪贴板
├─ 本机 OCR
├─ 官方体检进程适配
├─ 最小系统与故障记录适配
└─ 只读公开网络适配

CodexSOS.Core
├─ 证据与结果模型
├─ 官方体检允许字段解析
├─ 隐私遮盖
├─ 稳定搜索词提取
├─ 固定分类规则
├─ 相似度评分
├─ 安全建议
└─ 可公开报告生成
```

Core 不依赖 WPF 或 Windows，可以用虚构资料独立测试。App 负责会随 Windows、Codex 安装方式和外部服务变化的适配。

## 一次检查怎样流动

1. 用户点“帮我看看”。输入至少有截图或一句描述。
2. 截图在内存中交给本机 OCR。OCR 最长等待 12 秒，失败就返回空文字，其他检查继续。
3. 描述和 OCR 文字先遮盖一次。
4. 应用并行进行官方体检、最小系统收集、时间邻近 Windows 事件查询和 OpenAI 公开状态查询。
5. 固定规则把用户故障和官方体检状态分开判断。
6. 稳定词提取器对已经遮盖的内容去掉时间、路径、编号和随机串，只留下最多四个搜索词交给 GitHub 公共搜索。
7. 相似度规则比较固定短语、故障类别、使用方式、症状词和平台。只有证据达到门槛才显示“高度相似”。
8. 报告生成器组装允许字段，再对完整成品做第二次遮盖。
9. 结果页显示四块结论。截图引用在此时仍只存在于内存。
10. 用户主动打开保存预览后，才能选择把公开报告和隐私复核说明写到电脑。

任何支路失败都要回到结果页，不能把失败冒充成功，也不能因为某项绿灯覆盖用户看到的故障。

## 官方体检合同

官方 `codex doctor --json` 是 v0.1 唯一允许接触官方内部状态的黑箱进程。

Codex SOS 本身遵守下面的边界。

- 不执行 PATH 中任意同名文件。只接受 WindowsApps 中能读到 OpenAI 证书的程序，或官方 npm 包预期的 `node_modules\@openai\codex\vendor` 目录中的本机程序
- 参数固定为 `doctor --json`
- 使用不属于用户项目的中性工作目录
- 标准输出和错误各有 1,000,000 字符上限
- UI 最多等待 25 秒
- 超时后本次不再启动第二个官方体检
- 不把原始输出写到磁盘、日志或报告
- 只保留允许字段，并对每个用户可见字段遮盖

官方体检可能读取认证状态与会话元数据、联网探测，并在必要时维护登录状态。25 秒只是 SOS 的界面等待上限，不是对官方进程的强制运行上限。界面停止等待以后，真实官方进程自然结束，避免在维护登录状态时被强行打断。它的迟到结果不会重新进入本次判断。

完全虚构、与真实账号隔离的假进程可以在测试中被强制结束，用于证明测试框架不会被无穷等待拖住。这项测试不能照搬到真实官方体检。

支持的公开状态包括正常、警告、失败、不支持、等待过久、内容损坏、未知格式和不可用。每个状态只描述体检本身，不能直接充当用户故障根因。

## 数据最小化

允许的自动数据源如下。

- Windows 与 CPU 类型
- Codex 进程和安全可读版本
- PATH 中名为 Codex 的安装候选
- Windows Application 日志里的事件 1000、1001、1002，最长一小时、最多 40 条，最终只保留 8 条明确匹配 Codex 的结构化记录
- 官方体检的允许字段
- 用户主动提供的截图或描述
- OpenAI 状态页与 `openai/codex` 公共 issue

禁止源包括 `auth.json`、会话目录、完整聊天、提示词、项目代码、整个 `.codex`、Git 私有配置、浏览器资料和不相关 Windows 日志。

安装候选路径只用于本机聚类。公开结果只显示“Windows 应用安装”“命令行安装”等遮盖后的提示，不公开真实路径。同一 npm 安装里的 `codex` 和 `codex.cmd` 不能仅凭两条 PATH 结果判成重复安装。

## 网络合同

自动网络只有下面两类 GET。

- `https://status.openai.com/api/v2/summary.json`
- `https://api.github.com/search/issues`，限定 `repo:openai/codex is:issue`

GitHub 查询没有账号和请求正文。进入 URL 的只能是经过遮盖、截短和数量限制的稳定词。任何 POST、PUT、PATCH 或 DELETE 都是 v0.1 边界违规。

如果 GitHub 断网、限流或返回异常，结果页写“暂时无法完成搜索”，并准备一个同样经过遮盖的公开 issue 浏览器入口。程序不自动打开，也不把失败显示成“没有相似问题”。

Codex SOS 不使用 OpenAI SDK，不访问 OpenAI API，不读取 `OPENAI_API_KEY`。官方体检自己的网络探测仍属于官方进程行为。

## 规则而非模型

v0.1 不调用大模型。分类分值、相似度门槛和负断言都在源码与验收矩阵中公开。

- 截图稳定错误短语、明确的 Windows 故障记录、独立安装根与版本、官方体检提醒等得到固定分值。
- “卡了”“不能用”这类泛词不能单独形成结论。
- 两类证据无法区分时保持并列或写“暂时无法判断”。
- 官方体检全绿且没有其他足够证据时，固定输出“这份检查无法解释当前故障”。
- 没有搜到 issue 时固定输出“暂未找到足够相似的问题”。

详细门槛见 [`ACCEPTANCE_MATRIX.md`](ACCEPTANCE_MATRIX.md)。

## 发布形态

`dotnet publish` 生成 Windows x64 自带运行环境目录。用户可以解压 ZIP 后双击 `CodexSOS.exe`。安装包使用 Inno Setup 制作，每用户安装到 `%LOCALAPPDATA%\Programs\Codex SOS`，不需要管理员权限。

构建流程先实际运行虚构测试，再发布、移除调试和临时文件、扫描本机路径与秘密形状、生成文件清单和 SHA-256。构建不会启动真实官方体检，也不会自动上传或发布。

首个公开候选包没有商业代码签名的情况下，Windows 可能显示来源提醒。项目必须诚实说明，不能引导用户关闭安全保护。

## 有意延后

下面能力只保留接口或讨论空间，不在 v0.1 实现。

- 自由框选截图
- 中文截图 OCR
- 语音描述
- 一次重现过程的时间线记录
- macOS 与 Linux
- 自动提交或补充 GitHub issue
- 自动修复、删除、重置或重装
- 云端服务、账号体系和大模型判断

只有真实用户反馈证明价值以后再评估，不能为了功能表提前增加维护面。
