# Codex SOS v0.1 验收矩阵

本矩阵是公开前的硬门槛，不是演示脚本。全部测试只使用 [`tests/fixtures`](../tests/fixtures/README.md) 中的虚构资料。

当前自动回归已覆盖：路径后的固定短语、搜索三态与零请求、普通菜单截图零请求（`Settings`/`Version`/`Update`/`Login` 等界面字样不进搜索、版本流水号删除）、三句同分、陌生 doctor、隐私账单同源、浏览器排除/多窗口安全降级、远程 PATH 过滤和 Windows 清单声明，以及 17 份虚构 UI 场景夹具的整体加载校验。自动测试结果以最新 `RESULT: … passed; 0 failed` 为准；真实 doctor 仍明确 `NOT RUN`。真实 UI、真实截图识字与真实 doctor 的最终确认仍需干净 Windows 上的人工验收。

## 不可降级的总规则

- 官方体检自动运行，不用普通用户再做选择题。界面只显示“正在运行 Codex 官方体检”，不设置阻塞确认页。
- Codex SOS 自己不得打开或枚举 `auth.json`、会话目录、用户项目和 Git 配置；只接收官方体检子进程给出的输出并再次遮盖。
- 官方体检失败、不支持、超时或输出损坏时，应用必须继续到结果页，且最多尝试一次。
- 体检全绿只能说明“这次体检暂未发现异常”，不得写“Codex 没问题”。
- 截图、日志、项目内容和会话内容默认不上传；不得调用 OpenAI API，也不得要求 API Key。
- 自动动作仅限只读检查、经过遮盖的公开 issue 搜索和保存本机材料。不得删除、重置、重装、修改网络或自动发 issue。

## 十类可见 UI 场景

| 场景 | 夹具 | 实际操作 | 必须看到 | 必须证明 |
|---|---|---|---|---|
| 1. 有截图 | `01-screenshot-connection.json` + `stream-disconnected.svg` | 本机打开 SVG，复制画面后在 SOS 粘贴 | OCR 提取 `Stream disconnected before completion`；连接问题“可能有关” | 原图不进入公开报告；无上传请求 |
| 2. 只有一句话 | `02-description-only-task-recovery.json` | 输入一句中文后开始检查 | 任务恢复“可能有关”；建议保留会话和本地数据 | 不追加表格式提问 |
| 3. doctor 全绿 | `03-doctor-green-unexplained.json` | 运行完整流程 | “这份检查无法解释当前故障” | 不出现“Codex 没问题”或“没有故障” |
| 4. doctor 异常 | `04-doctor-warning-login.json` | 运行完整流程 | 描述和官方检查两条证据共同指向登录问题，最多说“很可能有关” | 不自动重置登录或删除资料 |
| 5. doctor 不支持 | `05-doctor-unsupported.json` | mock 返回不支持 `--json` | “这个版本暂不可用”，其他检查照常完成 | 不把不支持冒充用户故障根因，不强制升级 |
| 6. doctor 超时 | `06-doctor-timeout.json` | mock 官方体检不退出 | 到上限停止等待并进入结果页 | 只试一次；界面不假死；真实官方体检自然结束，避免强杀恰逢登录状态维护；总等待不超过 fixture 上限 |
| 7. doctor 损坏 | `07-doctor-malformed.json` | mock 返回破损文字 | “结果暂时无法读取”，其他检查照常完成 | 原始乱码和 canary 不出现在 UI、日志、报告和导出包 |
| 8. 高度相似 issue | `08-high-similarity-issues.json` | 使用离线 GitHub 返回值 | “3 个高度相似，其中 2 个仍未关闭”，每条有匹配理由 | 3 条均至少 75 分且满足固定短语＋同类故障 |
| 9. 无相似 issue | `09-no-similar-issue.json` | 返回只含泛词的无关结果 | “暂未找到足够相似的问题” | 不写“只有你遇到”或“没有别人遇到” |
| 10. 隐私拦截 | `10-privacy-block.json` | 输入多类虚构隐私后打开公开预览 | “我们准备公开这些信息”；确认前导出按钮不可用 | 所有原值在搜索、预览、报告和导出包中零命中 |

每条场景都必须额外断言：`resultPageReached=true`、没有执行 `forbiddenActions`、没有访问边界清单中的禁区、没有向 OpenAI API 发请求。

## 固定分类规则

### 先分开记录两件事

- `doctorState` 只描述官方体检本身：正常、警告、失败、不支持、超时、损坏或不可用。
- `incidentCategory` 描述用户遇到的问题：登录、连接、安装/版本、重复安装、桌面应用、Codex 服务、任务恢复、官方体检异常、体检正常但无法解释，或暂时无法判断。

两者不得互相覆盖。体检失败不等于用户故障由体检造成；体检正常也不等于用户没故障。

### 证据分值

| 证据 | 分值 | 限制 |
|---|---:|---|
| 两个不同真实安装根且版本不同 | 8 | 同一 npm 安装下的 `codex` 和 `codex.cmd` 只算一个 |
| 故障时间附近、且应用名明确对应 Codex 的 Windows 崩溃记录 | 8 | 模块名和异常码只是现象，不宣传根因 |
| doctor 某项明确 warning/fail | 6 | 必须与候选类别直接对应 |
| 截图中的固定错误码或完整稳定错误短语 | 6 | OCR 结果仍标为本机识别结果，不当作绝对正确原文 |
| 用户一句话中的高辨识度症状 | 4 | “卡了”“不能用”等泛词不得加 4 分 |
| 同时段官方状态事故 | 4 | 只作旁证；状态页绿灯不能排除个人故障 |
| 当前进程没运行、普通 `timeout`、泛词 | 1 | 单独不得形成结论 |

输出门槛：

- 8 分以上且至少有两个独立来源，或一个强本机事实与用户症状明确吻合：`很可能有关`。
- 5–7 分，或只有一条稳定错误短语：`可能有关`。
- 不足 5 分：`暂时无法判断`。
- doctor 全绿且没有达到 5 分的故障证据：`这份检查无法解释当前故障`。

### 冲突时的固定优先级

1. 先应用防误诊硬规则和时间范围，剔除无关、过时、OCR 不确定或互相矛盾的证据。
2. 具体、可复核的本机事实优先于泛泛描述：独立重复安装、精确任务恢复短语、明确登录异常、时间相符的桌面崩溃、固定连接错误短语。
3. doctor 的 warning/fail 只有在与用户描述或另一条证据一致时，才可把置信度提到“很可能有关”。
4. doctor 失败/不支持/超时/损坏仅在没有更强故障证据时显示为“官方体检自身异常”，并明确“不能解释原故障”。
5. 两类同分且无法区分时显示“可能与 A 或 B 有关”，不得硬选一个；没有足够证据则归“暂时无法判断”。

永久负断言：

```text
doctor 全绿 != Codex 没问题
doctor 失败 != 用户故障由 doctor 导致
没有搜到 issue != 没有其他人遇到
出现多个 codex.exe != 一定重复安装
当前没有进程 != 已发生崩溃
一次 HTTP 5xx != 已确认后台服务故障
OCR 文本 != 绝对正确的完整原始证据
公开 issue != OpenAI 已确认根因
```

## 公开 issue 相似度

搜索前必须先遮盖隐私，再删除时间、本机路径、用户名、版本流水号、会话号、请求号和随机串。只发送一个固定错误短语，或最多 3–5 个稳定词。

| 因素 | 分值 |
|---|---:|
| 正文中出现相同固定错误短语或错误码 | +45 |
| 同一故障类别 | +20 |
| 同为桌面版或同为 CLI | +10 |
| 三个以上高辨识度症状词重合 | 最多 +15 |
| 同为 Windows 或相关版本范围 | +10 |
| 平台、界面类型或症状明确矛盾 | 每项 -20 |

- `高度相似`：至少 75 分，且必须同时有固定短语/错误码和同一故障类别，issue 正文也支持该症状。
- `可能相关`：45–74 分，且至少有两组独立理由。
- `只是碰巧`：低于 45 分、只有标题支持、只有泛词，或正文与症状矛盾；结果页不计入相似数量。

`Codex`、`error`、`issue`、`problem`、`Windows`、`not working`、`crash` 等泛词不算高辨识度证据。open/closed、评论数和 issue 新旧不参与相似分，只单独展示。搜索断网或限流必须显示“暂时无法完成搜索”，不能冒充“没有相似问题”；此时只提供经过遮盖的浏览器搜索入口。

## 隐私遮盖验收

逐条样例见 [`redaction-cases.json`](../tests/fixtures/privacy/redaction-cases.json)，至少覆盖：Windows 用户路径、UNC 路径、邮箱、用户已提供的姓名/项目名/公司名、私有 Git 地址、内部网址、内网 IP、会话号、请求号、账号号、密码、Bearer 内容和长随机字符串。

公开前必须同时满足：

1. 原始 canary 在 GitHub 搜索参数、UI 公开预览、公开 Markdown、隐私说明、文件名和导出包中全部零命中。
2. 原截图、doctor 原始输出和 Windows 原始事件文本不进入公开包。
3. 简单预览只显示“发现 1 个邮箱、2 个路径”等数量，不重复展示原值。
4. 仍有高风险原文时禁止导出；全部自动遮盖后仍需用户看一眼并确认，因为程序不能保证 100% 认出人名和内部名称。
5. 私有临时材料与公开报告放在不同目录，公开包只从公开目录建立。

## 自动证明没有越界

边界数据见 [`forbidden-access.json`](../tests/fixtures/boundaries/forbidden-access.json)。CI 至少实现以下检查：

| 检查 | 做法 | 通过标准 |
|---|---|---|
| 不读 `auth.json`/会话/项目 | 在临时目录放 canary；记录 SOS 的打开、属性查询和目录枚举 | 禁止路径零访问；canary 在所有输出零命中 |
| doctor 进程边界 | 用假 `codex` 可执行文件模拟 7 种状态 | 只执行固定 `codex doctor --json`；原始 stdout/stderr 不落盘；超时后 UI 停止等待且本次不自动重启。仅对与真实认证完全隔离的假进程做强杀破坏测试；真实官方体检允许自然结束，避免恰逢官方维护登录状态时损坏数据 |
| 只有一个联网出口 | 注入 recording HTTP handler；静态检查禁止其他模块直接联网 | 仅允许脱敏后的 GitHub 公共 GET；无 POST/PUT/PATCH/DELETE；请求正文为空 |
| 不上传截图或日志 | 在图像和日志注入 canary，检查完整网络记录 | URL、请求头、查询和正文都无 canary 或文件字节 |
| OCR 不依赖网络 | 完全断网后跑虚构图片 OCR | 仍提取固定错误短语；网络记录为零 |
| 不用 OpenAI API | 设置虚构 `OPENAI_API_KEY` canary 并记录环境访问；封锁 `api.openai.com` | 不读取该变量；无 OpenAI SDK；封锁后主流程照常完成 |
| 发布包无本机残留 | 解包安装程序并扫描文本与二进制字符串 | 无构建机用户路径、PDB、canary、fixture、临时日志和私有材料 |

静态检查要验证业务代码只能通过受控文件模块和受控网络模块访问外界；运行时测试再验证实际行为。二者缺一不可。

## UI 留证格式

每个场景使用全新临时目录，保存以下可追溯证据：

```text
ui-evidence/UI-01/before.png
ui-evidence/UI-01/result.png
ui-evidence/UI-01/privacy-preview.png   # 仅适用时
ui-evidence/UI-01/run-receipt.json
```

`run-receipt.json` 至少记录 fixture ID、应用版本、开始/结束时间、doctor 状态、分类、相似结果数量、隐私发现种类、执行过的安全动作、被禁止动作计数、文件访问审计摘要和网络请求摘要。截图和回执在留存前也要跑 canary 扫描。

只有十类场景全部通过、安装包边界扫描通过，并由独立复核者确认没有“假诊断”，Gate 4 和 Gate 5 才能标记完成。
