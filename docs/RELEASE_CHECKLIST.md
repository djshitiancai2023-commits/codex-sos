# Codex SOS 公开前检查清单

这份清单用于 v0.1 本地 closeout 和以后版本发布。打勾必须有当前版本的证据，旧报告、口头说明、构建成功或某一项绿灯都不能代替。

## 1. 范围与身份

- [ ] 版本号、安装包文件名、应用内版本和 CHANGELOG 一致
- [ ] 仓库是独立 clean-room 项目，没有复制私有仓库历史、路径、提示词、数据或工作流
- [ ] README 和应用显著写明“非官方社区工具，与 OpenAI 无隶属关系”
- [ ] 没有 OpenAI 官方 Logo、官方授权暗示或误导性域名
- [ ] v0.1 仍只面向 Windows x64，没有混入服务器、账号、语音、跨平台、自动修复或自动提交 issue
- [ ] LICENSE、THIRD_PARTY_NOTICES、SECURITY、PRIVACY、CONTRIBUTING 与 CHANGELOG 齐全

## 2. 用户路径

- [ ] 干净 Windows 环境可以双击安装并从开始菜单启动
- [ ] 便携包完整解压后可以双击 `CodexSOS.exe` 启动
- [ ] 最终用户不需要 .NET、Python、OCR、命令行、GitHub 账号或 API Key
- [ ] 粘贴真实剪贴板图片可用
- [ ] 选择 PNG、JPG、BMP、TIFF 图片可用
- [ ] “截取正在打开的 Codex”只截目标窗口，失败时有粘贴和选图降级
- [ ] 本机 OCR 能从虚构英文错误图中提取稳定短语
- [ ] 一句中文描述可以完整走到结果页
- [ ] 正常流程没有技术表单或额外确认
- [ ] 若出现追问，最多一次，使用大白话选择题，只有一个推荐项并说明理由
- [ ] 结果页先回答四件事，用户不必展开技术材料

## 3. 官方体检

- [ ] 真实模式拒绝 PATH 中任意同名文件，只接受 WindowsApps 中能读到 OpenAI 证书的程序，或官方 npm 包预期 vendor 目录中的本机程序
- [ ] 参数固定为 `doctor --json`，工作目录不在用户项目中
- [ ] SOS 本身没有直接打开或枚举 `auth.json`、会话、聊天、提示词或用户项目
- [ ] 界面与隐私说明准确写明官方体检可能读取所需状态、联网并维护登录状态
- [ ] 原始标准输出和错误不落盘、不写日志、不导出
- [ ] 展示与导出只用允许字段，并经过二次遮盖
- [ ] 正常、警告、失败、不支持、等待过久、内容损坏、未知格式和不可用都有虚构测试
- [ ] UI 25 秒后停止等待并继续，本次不重复启动
- [ ] 真实官方体检超时后自然结束，不被强杀；迟到结果不重新进入本次结论
- [ ] 只有与真实认证完全隔离的假进程用于强制结束测试
- [ ] 体检全绿时不会出现“Codex 没问题”“没有故障”等错误保证

## 4. 数据与网络边界

- [ ] 文件访问测试证明 SOS 不读账号、会话、项目和整个 `.codex`
- [ ] Windows 事件查询只限 Application 的 1000、1001、1002，最长一小时、最多 40 条
- [ ] 只保留明确提到 Codex 的少量结构化事件，不保留原始 Windows 事件文本
- [ ] 安装候选路径仅用于本机判断，公开材料中没有真实路径
- [ ] 同一安装里的 `codex` 与 `codex.cmd` 不会被误判成两套安装
- [ ] 自动网络只含 OpenAI 状态页和 `openai/codex` 公共 issue 的 GET
- [ ] GitHub 请求无账号、无请求正文，发送前已经遮盖并缩成最多四个稳定词
- [ ] 网络记录里没有截图字节、完整描述、体检原文、Windows 原始事件或 canary
- [ ] 源码与运行记录都没有 OpenAI API、OpenAI SDK 或 `OPENAI_API_KEY` 读取
- [ ] 断网、限流和异常响应都有降级，不会冒充“没有相似问题”
- [ ] 没有 POST、PUT、PATCH、DELETE、自动打开浏览器或自动发布

## 5. 判断与建议

- [ ] 用户故障类别与官方体检状态分开保存和展示
- [ ] 固定规则、分值、相似度门槛和负断言与验收矩阵一致
- [ ] 高度相似 issue 同时满足稳定短语和同类故障，不只看标题关键词
- [ ] 公开 issue 被描述为用户报告，不冒充 OpenAI 已确认根因
- [ ] “没有搜索结果”不写成“只有你遇到”
- [ ] 一次 HTTP 5xx 不写成已确认服务端故障
- [ ] OCR 文字不冒充绝对正确的完整原文
- [ ] 建议只含低风险、可逆动作
- [ ] 没有自动删除、重置、重装、修改网络、改 Codex 数据或执行社区 workaround

## 6. 隐私与导出

- [ ] 截图只在内存中识别，重新开始或关闭后不再保留
- [ ] 原截图没有上传、落盘或进入公开报告
- [ ] 路径、用户名、邮箱、已知私人名称、私有 Git、内部网址、内网地址、编号、疑似密码和长随机串均有虚构测试
- [ ] 完整报告组装后再次整体遮盖
- [ ] 隐私预览只显示类别和数量，不重复原值
- [ ] 用户不点保存时不写出报告
- [ ] 保存时只产生公开报告和隐私复核说明
- [ ] 原截图、官方体检原文、Windows 原始事件、私有临时材料不在保存结果中
- [ ] 界面和文档明确说明自动遮盖不能保证 100% 安全
- [ ] 报告不会自动提交、上传或删除

## 7. 自动测试

- [ ] `scripts/test.ps1` 实际执行测试器，不只是完成编译
- [ ] 终端输出包含具体通过数量和零失败
- [ ] 所有正式 fixture 都声明为虚构资料
- [ ] 测试中的假官方体检不依赖真实 `CODEX_HOME`
- [ ] 边界 canary 在 UI、搜索 URL、报告、隐私说明和打包文件中零命中
- [ ] 静态扫描与运行时测试都通过
- [ ] 依赖漏洞检查已运行，结果和例外有记录
- [ ] 测试失败会让脚本和 CI 返回失败，不能继续标记发布通过

- [ ] UI-01　有截图，真实粘贴和本机 OCR
- [ ] UI-02　只有一句中文描述
- [ ] UI-03　官方体检全绿但解释不了当前故障
- [ ] UI-04　官方体检有异常
- [ ] UI-05　官方体检不支持
- [ ] UI-06　官方体检等待过久，界面先继续且不重启

每个场景都要满足下面这些条件。

- [ ] 使用全新临时目录和虚构资料
- [ ] 有开始画面、结果画面、需要时的隐私预览截图
- [ ] 有包含版本、时间、体检状态、分类、相似数量、隐私摘要、文件访问与网络摘要的运行回执
- [ ] 证明到达结果页、没有禁止动作、没有真实用户资料
- [ ] 截图和回执本身经过 canary 扫描

## 9. 打包检查

- [ ] Release、win-x64、自带运行环境、非裁剪、非单文件的发布参数符合架构决策
- [ ] 便携目录包含 `CodexSOS.exe` 和普通用户使用说明
- [ ] 安装包使用每用户目录，不要求管理员权限
- [ ] 安装、启动、卸载都在干净 Windows 环境真实走过
- [ ] 安装包与便携包没有 PDB、日志、转储、fixture、UI 证据或临时诊断材料
- [ ] 包内没有构建机用户名、真实路径、账号或 canary
- [ ] THIRD_PARTY_NOTICES 与上游许可证文本随最终二进制包提供
- [ ] 文件清单、包大小和 SHA-256 已生成

## 10. 独立复核

- [ ] 独立复核者能从证据重跑关键检查

- [ ] 复核者挑战了“是否比只跑官方体检多出明确价值”
- [ ] 没有为了显得聪明而强行分类或匹配 issue
- [ ] 没有收集普通用户感受不到收益的私人数据

- [ ] 所有 P0、P1 发现关闭并重测，P2、P3 有明确处置

## 11. 外部发布前停点

本地 closeout 完成后必须停下。不要自动创建远程仓库、推送、建立 Release、上传安装包或发布公告。

用户亲自做的最少事项如下。

1. 决定公开仓库的账号、仓库名和最终网址。
2. 决定首版是否购买代码签名。若不签名，确认公开页保留来源提醒和哈希核对说明。
3. 查看 README 首页、隐私说明和一套虚构 UI 演示，确认普通用户能看懂。
4. 手动创建或确认 GitHub 仓库，启用私密安全报告，再上传已经验收的源码与安装包。

发布后再验证一次 GitHub 页面、下载链接、SHA-256、安装与启动。外部发布是否完成必须以真实页面和下载结果为准，不能只凭本地脚本成功。
